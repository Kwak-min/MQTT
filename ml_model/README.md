# 위험 점수 MLP — 데이터 수집과 학습 절차

Gingerbread 노드는 BME680 센서값으로 "위험 점수(0~1)"를 계산하고, 점수에 따라 QoS를 고릅니다
(QoS 0·1은 UDP, QoS 2는 TCP). 이 문서는 직접 수집한 데이터로 그 점수 모델(5-5-1 MLP)을 학습하는 절차입니다.

> **현재 상태:** `firmware/include/mlp_weights.h`의 값은 **학습되지 않은 임시값**입니다
> (`MLP_WEIGHTS_TRAINED 0`, 다른 AI가 만든 숫자). 아래 절차를 마치면 학습된 값으로 교체되고,
> 부팅 시 시리얼에 "학습된 값"이라고 표시됩니다.

## 입력 특징
| 특징 | 단위 | `--features` | 성격 |
|---|---|---|---|
| 온도 | °C | `temp` | 고온 위험의 직접 지표. 가스 히터 자체 발열로 몇 °C 높게 읽힘 |
| 습도 | % | `hum` | 열풍기 가열 시 함께 떨어져 온도와 상관됨 |
| 가스 저항 (절대값) | kΩ | `gas` | 기준값이 개체·예열·환경에 따라 크게 달라 **세션 간 일반화가 약함** |
| 기압 | hPa | `pres` | 날씨·고도에 따라 변함. 위험의 직접 지표가 아니며 세션 지문이 될 수 있음 |
| **가스 비율** | 0~1 | `gasr` | **가스 저항 ÷ 기준값.** 세션마다 다른 기준값을 상쇄함 |

앞의 4개가 BME680이 측정하는 값 전부이고, `gasr`은 가스 저항에서 파생한 값입니다.
**기본은 `temp,hum,gasr`** 입니다 (아래 실험 근거). 다른 조합은 `--features`로 고를 수 있습니다.

### 가스 비율이란
```
비율 = 현재 가스 저항 / 기준값        (1이면 깨끗한 기준 상태, 작을수록 가스 증가)
기준값 = max(현재값, 이전 기준값 × (1 - 0.00016))   ← 오르면 즉시 따라가고, 내릴 땐 아주 천천히 감쇠(반감기 약 6시간)
```
- 정의는 `firmware/include/gas_baseline.h` **한 곳**에만 있고, 파이썬(`ml_model/gas_baseline.py`)이 그 파일에서
  상수를 읽어 똑같이 계산합니다. `verify_export.py`가 g++로 둘을 대조합니다 (학습에 쓴 값 = 실기에서 계산될 값).
- **예열:** 부팅 후 처음 120샘플(5초 주기로 약 10분)은 비율이 1.0으로 고정됩니다 (기준값이 아직 불안정).
  그 시간 동안 가스 이상은 감지하지 못하고 온도/습도는 정상 동작합니다. 학습에서도 이 구간 행은 뺍니다.
- **한계:** 가스가 수 시간 지속되면 기준값이 감쇠해 비율이 다시 1에 가까워집니다. 부팅하면 기준값이 초기화됩니다.

### 합성 데이터 실험이 보여준 것 (실제 데이터가 아니라 도구 검증용, 상대적 경향만 참고)
새 세션을 통째로 검증용으로 뺐을 때(세션마다 정상 가스 기준값 60~160 kΩ):

| 특징 | 새 세션 검증 F1 |
|---|---|
| 온도 + 가스비율 | 1.000 |
| 온도 + 습도 + 가스비율 (**기본**) | 0.994 |
| 온도 + 습도 + 가스저항(절대값) | 0.812 |
| 온도 + 습도 + 가스저항 + 기압 | 0.647 |
| 온도만 / 가스비율만 | 0.690 / 0.631 |

- 가스 **절대값**은 새 세션에서 무너지고, **비율**은 버팁니다.
- 기압은 세션을 구별하는 "지문"이 되어 같은 세션 안의 검증만 부풀렸습니다.
- **고온 위험과 가스 위험이 함께 있으면 한 특징으로는 한쪽밖에 못 잡습니다** (온도만 0.69, 가스비율만 0.63).
- 위 점수는 제가 만든 깨끗한 합성 데이터의 것입니다. 실제 데이터의 절대 성능을 뜻하지 않습니다.

## 1. 위험의 정의를 먼저 정하세요 (논문에 그대로 쓰입니다)
| 라벨 | QoS | 의미 | 정의 (직접 정하세요) |
|---|---|---|---|
| 0 정상 | 0 | 평상시 | ___ |
| 1 경고 | 1 | 이상 징후 | ___ |
| 2 위험 | 2 | 위험 | ___ |

- **고온**: 예) 정상 < 35°C, 경고 35~50°C, 위험 ≥ 50°C (기준 온도계가 있으면 그것으로)
- **가스(VOC)**: **"정상 상태 대비 얼마나 떨어졌나"** 로 정의하세요. 예) 기준의 75% 이하 경고, 40% 이하 위험.
  (가스비율이 바로 이 값입니다.)
- **복합**: 둘 다일 때는 더 높은 쪽 라벨.

### 라벨링 방식 두 가지 (논문에 어떤 방식이었는지 적어야 합니다)
- **수동(권장)**: 실험 상황을 보고 키 `0/1/2`로 라벨을 바꿉니다. 경계 부근은 사람의 판단이라 약간 흔들립니다.
- **자동 `--auto-bands LOW HIGH`**: **온도만으로** 라벨을 자동 지정합니다. 가스 시나리오에는 쓸 수 없습니다(가스는 수동으로).
  라벨이 입력(온도)의 함수라 모델은 온도 구간 규칙을 재현하므로, 쓴다면 "온도 구간으로 정의했다"고 명시하세요.

## 2. 수집용 펌웨어 업로드
```
cd firmware
pio run -e board1_collect -t upload
```
이 펌웨어는 네트워크 없이 BME680 값 4개(`온도,습도,가스,기압`)를 5초마다 시리얼로 출력합니다. **5초 주기는 실제 동작과
같게 맞춘 것입니다** — BME680 가스 히터의 자체 발열이 온도 오프셋을 만들고, 가스 기준값도 샘플 단위로 계산되므로
주기가 다르면 학습한 값이 실기에서 어긋납니다. (`main_gingerbread.cpp`와 센서 설정도 동일합니다.)

## 3. 수집
```
python ml_model/collect.py --list-ports          # 포트 확인 (예: COM5)
python ml_model/collect.py --port COM5           # 수집 시작
```
키(창을 클릭한 상태): `0` 정상, `1` 경고, `2` 위험, `p` 일시정지, `q` 종료.
결과는 `ml_model/data/raw_dataset.csv`에 이어쓰기됩니다 (컬럼: `timestamp,session,ms,temp,hum,gas_kohm,pres_hpa,label`).

> **중요: 라벨을 누르지 않은 동안에도 값은 `label = -1`로 저장됩니다.** -1은 "라벨 없음"이라 학습에는 쓰이지 않지만,
> 가스 기준값이 시계열의 연속성에 의존하므로 **샘플이 빠지면 학습할 때 계산한 비율이 실기와 달라집니다.**
> 그러니 **수집 프로그램은 세션 내내 켜 두고**, 쉬는 구간은 `p`로 일시정지하세요 (끄지 마세요).
> 수집이 30초 넘게 끊기거나 보드가 재부팅되면 그 지점부터 기준값을 새로 시작합니다 (재부팅은 실제와 같게 동작).

### 수집 계획 (권장): 원인을 하나씩 바꿔 서로의 상관을 끊으세요
| # | 시나리오 | 라벨 | 목적 |
|---|---|---|---|
| 0 | **예열: 켜고 10분 이상 라벨 없이 둠** | (-1) | 가스 기준값이 자리잡게 함 (예열 구간은 학습에서 제외됨) |
| 1 | 평상시 상온 20분+ | 0 | 기준 |
| 2 | 입김/젖은 수건으로 **습도만** 올림 | 0 | "습도가 높다 ≠ 위험"을 가르침 (음성 예시) |
| 3 | 열풍기로 **온도만** 천천히 올림 (오를 때 1, 목표 초과 시 2) | 1 → 2 | 고온 위험 |
| 4 | 식히기 (내려가는 구간도 수집) | 온도에 맞게 | 오를 때/내릴 때 차이 |
| 5 | 상온에서 **가스만** 변화 (소량 알코올 솜을 센서 근처에) | 1 → 2 | 가스 위험 |
| 6 | 가열 + 가스 동시 | 2 | 복합 |

- **시나리오 사이에는 `p`로 라벨을 끄세요.** 가스 이벤트 직후 센서가 회복되는 동안은 값이 아직 정상이 아니므로
  라벨 없이(-1) 두고 회복을 기다린 뒤 다음 시나리오로 가세요.
- **세션을 여러 번**: 최소 3회, 서로 다른 시간/방/날. 같은 세션의 연속 샘플은 거의 같아서 세션이 하나뿐이면 검증을 믿을 수 없습니다.
  **마지막 세션 하나는 학습에 쓰지 말고 `--val-sessions`로 검증에만 쓰세요.**
- 클래스마다 **최소 30개**(권장 200개 이상)가 없으면 `train.py`가 헤더를 내보내지 않습니다.

### 안전 (가스 시나리오는 특히 주의)
- BME680 동작 범위는 -40~85°C입니다. **센서 온도를 70°C 이하로 유지**하세요. 열풍기는 충분히 떨어뜨리고,
  보드(ESP32)와 USB 케이블에 직접 열을 쏘지 마세요.
- **가스는 소량의 알코올 솜(손소독제 등)만 쓰세요.** 라이터 가스, 부탄, 스프레이 등 **가연성 가스는 쓰지 마세요.**
  환기가 되는 곳에서, 열원과 함께 쓰지 말고(시나리오 6은 알코올을 열원에서 멀리 떨어뜨려 소량으로), 불꽃 근처에서는 절대 하지 마세요.
- 밀폐된 곳, 가연물 근처에서는 가열하지 마세요.

## 4. 학습
먼저 **어떤 센서값이 실제로 도움이 되는지** 데이터로 확인하세요.
```
python ml_model/train.py --compare-features                              # 같은 세션 안의 시간순 검증
python ml_model/train.py --compare-features --val-sessions <새 세션 ID>   # 새 세션 통째로 검증 (더 엄격)
```
표에서 특징을 더했는데도 새 세션 성능이 오르지 않으면 그 특징은 쓰지 마세요. 그다음 학습:
```
python ml_model/train.py --val-sessions <새 세션 ID>                     # 기본: 온도, 습도, 가스비율
python ml_model/train.py --features temp,gasr --val-sessions <새 세션 ID>  # 다른 조합
```
- 세션 ID는 `collect.py`를 실행한 시각(예: `20260922-103015`)이며 CSV의 `session` 컬럼에 있습니다.
- QoS 임계값(경고/위험 경계)은 학습 데이터에서 자동으로 정해 헤더로 내보냅니다.
- **특징 하나만 쓰는 임계값 규칙과 자동 비교**합니다 (방향도 자동 판정). 가장 좋은 단일 규칙과 비슷하면
  "사실상 같습니다"라고 나옵니다. 그때 이 프로젝트의 ML은 "임계값을 데이터로 보정"한 것이지 규칙을 넘어선 것이 아닙니다.
  고온과 가스 위험을 함께 다룰 때는 단일 특징 규칙이 한쪽밖에 못 잡으므로 MLP의 이점이 나타날 수 있습니다.
- 결과: `firmware/include/mlp_weights.h`(펌웨어용), `ml_model/data/train_report.json`(지표·분할·해시·세션 편차),
  `ml_model/data/mlp_model.npz`(검증용). **세 파일과 `raw_dataset.csv`를 함께 저장소에 커밋**하세요.

## 5. 내보낸 코드 검증 (보드 없이, 업로드 전에 필수)
```
python ml_model/verify_export.py
```
PC의 g++로 펌웨어 코드를 컴파일해 파이썬과 대조합니다.
1. 신경망 순전파 (C++ vs 파이썬), 2. 헤더 값 손상 여부, 3. QoS 임계값 일치,
4. **가스 기준값 추적기 (C++ vs 학습에 쓴 파이썬)** — 5개 시나리오(잡음, 가스 발생, 예열 상승, 무효값, 무작위).
오차 5e-5 미만이면 통과입니다. 실패하면 업로드하지 마세요.

```
cd firmware

```
시리얼 모니터의 부팅 로그에서 반드시 확인:
```
[MLP] 가중치: 학습된 값 (ml_model/train.py 생성)      ← "⚠ 경고: ... 임시값"이 보이면 헤더가 안 바뀐 것
[MLP] QoS 임계값: QoS1 >= 0.xxx | QoS2 >= 0.xxx
```
추론 로그의 `가스비율`이 **부팅 후 약 10분 동안 1.000**이다가 그 뒤부터 변하는지, 그리고 **상온에서 QoS 0**,
가열/가스 자극 시 QoS 1 → QoS 2(TCP)로 바뀌는지 직접 확인하세요.

## 7. 논문에 쓸 때
- 이 모델은 **직접 수집한 N개 샘플(세션 M개, 조건 ...)로 학습한 5-5-1 MLP**이며, 사용한 특징과 라벨 정의(수동/온도 구간)를 밝힌다.
- 가스 저항은 **기준값 대비 비율**로 썼다고 밝히고, 기준값 추적 방식(최댓값 추적 + 반감기 약 6시간, 예열 10분)과 한계를 적는다.
- 분할 방식, **새 세션에서의 검증 성능**, 단일 특징 규칙과의 비교(`train_report.json`)를 함께 보고한다.
- 합성 데이터나 다른 AI가 만든 가중치를 학습 결과처럼 서술하지 않는다.
- 가스 저항이 개체·예열·환경에 민감하다는 한계와 대응(비율 사용, 예열, 세션 편차 확인)을 밝힌다.
- 학습·검증 데이터가 한 장소/기기에서 수집됐다는 한계를 밝힌다.
