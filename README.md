# 🚀 펌웨어 업로드 및 트러블슈팅 가이드

## 1. 하드웨어 연결 및 타겟 빌드 절차
1. 테스트할 ESP32-S3 보드 1개만 컴퓨터와 USB-C 케이블로 연결합니다. (혼선 방지를 위해 다른 보드는 분리)
2. 본인이 빌드할 소스 파일 상단의 와이파이 정보를 현재 핫스팟 세팅값으로 수정 후 저장(`Ctrl + S`)합니다.
   - 1번 보드 작업 시: `firmware/src/main_gingerbread.cpp` 수정
   - 2번 보드 작업 시: `firmware/src/main_standard_MQTT.cpp` 수정
3. Antigravity IDE 최하단 파란색 상태 표시줄에서 현재 지정된 환경 이름(예: `Default` 또는 `env:...`)을 클릭합니다.
4. 화면 상단에 팝업창이 열리면 목적에 맞는 타겟을 마우스로 선택합니다.
   - 1번 보드 테스트 시: `board1_gingerbread` 선택
   - 2번 보드 테스트 시: `board2_standard` 선택
5. 하단 파란색 바의 오른쪽 화살표 아이콘(`➔` Upload 버튼)을 클릭하여 업로드를 시작합니다.
6. 업로드 완료(`[SUCCESS]`) 문구가 뜨면, 옆의 플러그 모양 아이콘(`Serial Monitor`)을 눌러 로그 창을 켭니다.

## 2. 자주 발생하는 에러 해결법 (트러블슈팅)

### 🚨 에러 1: Failed to connect to ESP32-S3: No serial data received.
- **원인**: 보드가 프로그램 연산에 집중하느라 컴퓨터의 다운로드 신호를 받지 못하는 현상입니다.
- **해결책 (강제 부트로더 진입)**:
  1. 보드 기판의 `BOOT` 버튼을 누르고 있는 상태를 유지합니다.
  2. 그 상태에서 `RST`(또는 `EN`) 버튼을 1초간 꾹 눌렀다가 뗍니다.
  3. 누르고 있던 `BOOT` 버튼에서 손을 뗍니다.
  4. IDE 하단의 `➔` (Upload) 버튼을 다시 클릭합니다.

### 🚨 에러 2: PermissionError(13, '장치가 명령을 인식하지 않습니다.') / 시리얼 모니터 먹통
- **원인**: 보드가 재부팅되거나 케이블이 일시 단선되면서 윈도우 가상 COM 포트 인식이 꼬인 현상입니다.
- **해결책 (포트 드라이버 리셋)**:
  1. 현재 켜져 있는 시리얼 모니터 터미널 창을 클릭하고 `Ctrl + C`를 눌러 세션을 강제 종료합니다. (또는 우측 상단 휴지통 아이콘 클릭)
  2. 컴퓨터에 꽂힌 보드의 USB-C 케이블을 완전히 뽑아냅니다.
  3. 3초 대기 후 케이블을 다시 꽉 결합합니다. (컴퓨터 장치 연결음 확인)
  4. 하단 플러그 아이콘을 눌러 시리얼 모니터를 새로 가동한 뒤, 보드의 `RST` 버튼을 딸깍 1번 눌러줍니다.
